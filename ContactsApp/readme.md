# ContactsApp
Я постарался выполнить задание с как можно лучшей структурой, возможностью для масштабирования.
Ссылка на скачивание релизного APK: https://github.com/panvkk/yadro-2026/raw/refs/heads/main/ContactsApp/app/release-apk/app-release.apk

## Функциональные требования

### 1. Разработать приложение, которое будет отображать данные о контактах, сохраненных на устройстве в виде списка, пункты которого отображают краткую информацию о каждом контакте. — **DONE**

#### Критерии приемки:
* в списке должны отображаться только контакты хранящиеся на устройстве — **DONE**
* пользователь может видеть краткую информацию о каждом контакте в соотвествии с требованиями — **DONE**

### 2. Реализовать звонок на номер(номер по умолчанию, мобильный), который отображается у контакта в общем списке по нажатию на пункт списка. — **DONE**

#### Критерии приемки:
* Звонок должен начаться по клику на пункт списка — **DONE**
* Звонок должен осуществляться по номеру, указанному в пунке списка (main phone number) — **DONE**

## Нефункциональные требования

1. Реализовал весь функционал на Compose, использовал DI через Hilt. Приложение выполнено строго в Clean Architecture, с разделением на слои data, domain, presentation.
2. Для отображения только тех контактов, которые сохранены на устройстве, я пошёл по одному из 2 пути - выбирать в ContactsContract только те, у которых ACCOUNT_TYPE равен одному из типов аккаунта вендеров(привязанные к аккаунту это и есть хранящиеся на устройстве). Проблема в том, что вендеров очень много и сделать 100% идеальное решение невозможно, но я постарался выбрать самые распространенные вендеры. Также вторым путём было выбирать наоборот - те ACCOUNT_TYPE'ы, которые не равны таким как google, telegram, viber и прочее. Однако, так как приложений тоже огромное количество, поэтому такое решение не особо лучше.
3. Отображаю краткую информацию(имя и номер телефона), а также аватар пользователя, использую для этого библиотеку Coil.
4. Звонок осуществляется по номеру, отображенному в списке. Но так как в тз не было указано обратного, в UI я храню только один номер, который выбираю в ContactsDataSource. Для каждого контакта я оставляю мобильный номер(как указано в тз) или любой другой, если мобильного не нашлось.
5. Кроме того, я поработал с пермишонами, чтобы пользователь понимал, что от него требутеся. В итоге довёл всё практически до идеала (каюсь, не хватило времени, чтобы добавить кнопку "перейти в настройки", если пользователь дважды отклонил доступ к контактам/звонкам. На это попросту не хватило времени).
